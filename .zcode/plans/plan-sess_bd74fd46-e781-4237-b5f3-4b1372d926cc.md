# Workflow irregularity fixes — surgical amendment of the build workflow

## Context

Three incidents in two days exposed fragile mechanics in the build workflow script (`.zcode/workflow-drafts/Take-stock-of-the-build.dwf.ts`): two cache-frontier resets (~12.4M wasted tokens) and, just now, a run-killing gate timeout. A fresh-eyes audit (independent agent, full script read) produced 19 findings. The live run `dwfrun-9c94f36f` is **errored** on the audit's #2 finding — the per-task full-suite gate (now 455 tests / ~387s) exceeds the script's default 300s `world.run` timeout. `ResumeWorkflowRun` refuses errored runs, so an `AmendWorkflow` is required regardless — this plan makes that amendment carry all the fixes.

Key audit verdict adopted: a blanket skip-restructure would reset the cache frontier again — **but** it is safe for exactly tasks **1.6–2.2**, whose ask records don't exist in the current chain (frontier sits just after 1.5). Their "verify" re-dispatches buy nothing (the tree is already proven: 455 tests green, smoke 14/14, ruff clean).

## Changes — one file only: `.zcode/workflow-drafts/Take-stock-of-the-build.dwf.ts`

1. **Timeout hardening (audit #2, #14 — the error cause):** `fullSuiteGreen()` passes `timeoutMs: 1_800_000` to pytest and ruff and **returns the captured output** so the fix-loop reuses it instead of re-running both commands; the post-fixer smoke re-run and every remaining gate `world.run` get explicit timeouts.
2. **Targeted skip:** tasks **1.6–2.2** (`alreadyDone: true`) dispatch **no worker ask, no per-task gate, no dirty-tree check** — only status/report. Tasks **1.4 and 1.5 keep byte-identical asks** (their records settle from cache). Safety net unchanged: M2 smoke gate + delta reviewer run after 2.3/2.4; release gate runs the full suite.
3. **Robustness guards (audit #1, #3, #19):** `gh auth status` wrapped in try/catch (spawn failure feeds `exitCode: -1` to the captain instead of killing the run); malformed ask results guarded (`Array.isArray`/optional chaining on `outcome.summary`, `review.findings`, `sweep.findings`/`method`); worker returning `committed === false` with a green suite becomes a blocker, not a silent "done".
4. **Release hardening (audit #5, #6, #16, #17):** deterministic keys check before the captain — `git ls-files`/`check-ignore` over `state/` and `**/keys.json`, blocker if tracked (spec §6.5 contract, no longer prose-only); captain pushes the **current branch** after verifying it, escalates otherwise; release-prep reuses an existing `v1.0.0` tag (verify points at HEAD) instead of failing on re-run; blocker conclusion derived from `verified` contents.
5. **Reporting integrity (audit #8, #9, #13, #15):** `openFindings` actually populated from reviewer/sweep findings; `verified` seeded from a baked constant (fast-forward doesn't re-run plain code — per-task gate lines would otherwise vanish from the final report); `fixedCount` from the fixer's own returned list; round caps removed from ask text (stay in control flow — amend-tunable without cache churn).
6. **Research-spike variant (audit #18):** spike rows (3.0/4.0) get a read-only research instruction — no app-code edits, no TDD/commit demands (byte change safe: no cached records).
7. **2.3 continuity (byte change safe):** 2.3's brief gains a note that a prior worker session left partial work/uncommitted files — inspect `git status` first, finish TDD-style, commit.
8. **Frozen (audit #4, #10 — mid-chain hazards):** phase-1 `git log -5` bytes untouched; no `alreadyDone` flips for tasks with chain records; `DONE_AT_START` extension deferred to future fresh-run decisions, protocol written to the ledger.
9. **Documented deviations (audit #11, #12):** GUI sweep stays post-loop only (M2–M4 covered by offline HTTP smokes; deviation listed in handoff `notCovered`); D11 loop-count noted as literal-vs-spirit (fixed arrays are bounded).

## Implementation sequence (build mode)

1. Apply all edits to the script file.
2. `AmendWorkflow(run_id="dwfrun-9c94f36f-7808-494f-85a4-d4911ca33122", path=…)` — supersede the errored run, importing its settled records (phase-1 git-log, 1.4/1.5 verify asks + gates).
3. One `GetWorkflowRun` snapshot to verify: `cached_steps > 0`, worker-1.4/1.5 settle rather than re-run, run advances to 2.3 (real work), tokens near-zero until 2.3.
4. Update ledger + memory: new run id, adopted findings, the mid-chain amend protocol (what may never change).
